## 1. Start the stub ingest server

From the repo root (Python 3.9+ stdlib only):

```bash
python3 scripts/stub-ingest-server.py --port 8787
```

- **Health:** `GET http://127.0.0.1:8787/health`
- **Ingest:** `POST http://127.0.0.1:8787/api/v1/ingest/transactions`
- **Logs:** `logs/ingest/ingest-YYYY-MM-DD.jsonl` (gitignored)

Smoke test with a fixture:

```bash
curl -sS -X POST http://127.0.0.1:8787/api/v1/ingest/transactions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer churney_dtk_spike_dev_only" \
  -d @docs/spikes/fixtures/cad-with-merchant.json | jq .
```

Expected: `201` with `"status": "accepted"`. Replaying the same `idempotency_key` returns `200` / `"status": "duplicate"`.

## 2. Expose stub to iPhone (tunnel)

The phone cannot reach `localhost` on your dev machine. Use a tunnel:

### Option A — ngrok (common)

```bash
ngrok http 8787
```

Copy the `https://….ngrok-free.app` URL. The Shortcut will POST to:

```
https://<tunnel-host>/api/v1/ingest/transactions
```

### Option B — Cloudflare Tunnel

```bash
cloudflared tunnel --url http://127.0.0.1:8787
```

Use the printed `https://….trycloudflare.com` hostname the same way.

> **Spike note:** Any HTTPS tunnel works. Production will use the real Vercel host; this spike only needs a reachable URL + JSON POST.

## 3. Wallet Transaction trigger — what Apple exposes

Per [Apple Support — Transaction triggers](https://support.apple.com/guide/shortcuts/transaction-trigger-apd65c67538a/ios) and community testing (iOS 17+):

| Shortcut Input property | Maps to ingest field | Notes |
|---|---|---|
| **Card or Pass** | `card_ref.match_hint` (via user dictionary) | Wallet card display name; user maps to a hint like `amex_gold` |
| **Merchant** or **Name** | `merchant` | Often identical to **Transaction**; may be **empty** on some taps |
| **Amount** → *Currency Amount* | `amount_minor` | Decimal string in charged currency; convert to integer cents |
| **Amount** → *Currency Code* | `currency` | ISO 4217 (e.g. `CAD`, `USD`) |
| *(automation run time)* | `occurred_at` | ISO 8601 UTC ≈ tap time |
| *(generated per run)* | `idempotency_key` | UUID v4 |

**Not available from Wallet:** PAN, full card number, MCC, lat/long. Card identity is the Wallet label the user configures.

**Coverage:** NFC / in-store Apple Pay taps only. Online, in-app, and physical swipe without Apple Pay are **not** captured (Spec 01 §1).

## 4. Build the Shortcut (step-by-step)

### 4.1 Create the automation

1. Open **Shortcuts** → **Automation** tab → **+** → **Transaction**.
2. **When I tap:** choose **Any Card** (or specific cards for testing).
3. Enable **Run Immediately** (required — see failure modes).
4. Disable **Notify When Run** (optional; reduces noise during spike).
5. Create a **New Blank Automation** (starts with Shortcut Input = transaction).

### 4.2 Card → `match_hint` dictionary

Wallet gives a **Card or Pass** string (e.g. `Amex Gold`). Maintain a **Dictionary** action:

| Key (Wallet card name) | Value (`match_hint`) |
|---|---|
| `Amex Gold` | `amex_gold` |
| `TD Visa Infinite` | `td_visa_infinite` |

Add **Get Dictionary Value** with key = **Card or Pass** from Shortcut Input → variable `match_hint`.

> Phase 1 will replace this with an in-app setup wizard; for the spike, hard-code your cards.

### 4.3 Merchant (nullable)

1. **Get Variable** → Shortcut Input → **Merchant** (fallback: **Name**).
2. **If** Merchant is empty → set `merchant` to **Nothing** (JSON `null`).
3. **Otherwise** pass the string through.

Document which issuers/merchants return empty names during device testing.

### 4.4 Amount + currency (including FX)

1. From Shortcut Input → **Amount** → select **Currency Amount** (not the raw Amount wrapper).
2. From Shortcut Input → **Amount** → select **Currency Code** → `currency`.
3. **Replace Text** on Currency Amount: remove non-digits except `.` (regex `[^\d.]` per region).
4. **Calculate** × 100 and **Round** → integer `amount_minor`.

For a **US$35.00** tap on a CAD card, Wallet reports `currency=USD`, `amount_minor=3500` — server FX handling is Phase 1; spike only needs correct capture.

### 4.5 Timestamp + idempotency

1. **Current Date** → format **ISO 8601** → `occurred_at`.
2. **Generate UUID** → `idempotency_key`.

### 4.6 Assemble JSON body

Use **Dictionary** (or **Text** with JSON template) with keys matching Spec 01:

```json
{
  "idempotency_key": "<UUID>",
  "device_token": "churney_dtk_spike_dev_only",
  "card_ref": { "match_hint": "<from dictionary>" },
  "merchant": "<string or omit for null>",
  "amount_minor": <integer>,
  "currency": "<ISO code>",
  "occurred_at": "<ISO 8601>",
  "client_meta": {
    "shortcut_version": "0.1.0-spike",
    "locale": "en_CA"
  }
}
```

### 4.7 POST to stub

1. **Get Contents of URL**
   - URL: `https://<tunnel-host>/api/v1/ingest/transactions`
   - Method: **POST**
   - Headers: `Content-Type: application/json`, `Authorization: Bearer churney_dtk_spike_dev_only`
   - Request Body: JSON from previous step
2. *(Optional spike)* **Show Result** or append response to a Notes file for debugging.

### 4.8 Retry (spec-aligned, optional for spike)

Spec 01 calls for **one retry** on network failure. For spike, a single POST is enough; note in 0.2 whether retry is needed in practice.

## 6. Failure modes (documented for 0.2 probe)

Sources: Spec 01 §2.1, [FB16379100](https://feedbackassistant.apple.com/feedback/16379100) (Wallet delay / timeout), field reports.

| Failure | Symptom | Likely cause | Spike / product mitigation |
|---|---|---|---|
| **Delayed transaction data** | Automation does not run, or runs with empty fields | Bank → Apple Wallet posting delay | Daily digest + manual add (Phase 1); quantify in 0.2 |
| **Trigger timeout** | Shortcut errors or silent no-op | FB16379100 class issues when Wallet data slow | Same as above; log iOS version + issuer |
| **Empty merchant** | `merchant` null | Issuer/merchant not in Wallet feed | `status=draft` in Phase 1; user confirms |
| **Merchant ≡ Name ≡ Transaction** | Redundant fields | Apple API quirk | Prefer **Merchant**; fall back to **Name** |
| **Amount parse failure** | "Conversion Error" in Shortcuts | Picked whole transaction object instead of **Currency Amount** | Re-map fields per §4.4 |
| **Wrong sign on refunds** | Positive amount for refund | Wallet/issuer inconsistency | Normalize server-side (Spec 01 §2.1) |
| **Run Immediately off** | Prompt every tap | User setting | Setup wizard enforces with screenshots |
| **Offline tap** | No POST; tap lost | No offline queue in Shortcuts | Weekly reconciliation nudge |
| **Tunnel down** | HTTP error in Shortcut | Dev env only | Production uses stable HTTPS host |
| **Double automation fire** | Duplicate payloads | iOS/automation quirk | `idempotency_key` dedupe (stub returns 200) |

## 7. Device validation checklist (human)

Run on a physical iPhone (iOS 17+, Wallet card enrolled). Check each box and attach evidence to the PR or 0.2 log.

- [ ] Stub server running + tunnel URL verified from phone browser (`/health`)
- [ ] Automation created with **Transaction** trigger + **Run Immediately**
- [ ] **T1** — CAD tap: `card_ref`, `merchant`, `amount_minor`, `currency` present in `logs/ingest/*.jsonl`
- [ ] **T2** — Empty merchant case captured at least once (or document "not observed" with 10+ taps)
- [ ] **T3** — FX tap: non-CAD `currency` with correct minor units
- [ ] Screenshot of Shortcut actions (card dictionary, POST step)
- [ ] Note iOS version, device model, card issuer(s) tested
